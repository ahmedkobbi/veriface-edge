## About Me

I'm a full-stack engineer and security architect focused on **privacy-preserving biometric authentication**. I build systems where the server never sees raw biometric data — only zero-knowledge proofs and end-to-end encrypted payloads.

My flagship project, **[VeriFace Edge](https://github.com/ahmedkobbi/veriface-edge)**, is a production-grade facial authentication SaaS platform featuring post-quantum cryptography (ML-DSA-87 / FIPS 204), PLONK zero-knowledge proofs, a server-side signing proxy, and 8 cross-platform SDKs — all hardened through 4 rounds of adversarial penetration testing (88 findings identified and remediated).

### What I Do

- **Biometric Security** — On-device face authentication with rPPG liveness, PAD (presentation attack detection), and anti-injection defense
- **Post-Quantum Cryptography** — ML-DSA-87 hybrid signatures (FIPS 204), PLONK zk-SNARKs, Ed25519/X25519, AES-256-GCM
- **Security Architecture** — OWASP Top 10 (10/10 PASS), FIPS 140-3 readiness, SOC 2 Type II preparation, GDPR crypto-erasure
- **Platform Engineering** — Kubernetes, Docker, CI/CD with Sigstore signing, Trivy scanning, SBOM generation
- **Multi-Platform SDKs** — Web, React Native, iOS (Swift), Android (Kotlin), Flutter (Dart), Python, Go, Rust

## Security Philosophy

> **Privacy by design, security by default.** The server should never have access to raw biometric data. Authentication should be provable without revealing identity. Cryptography should resist quantum attacks. Every line of security-critical code should be audited, signed, and verifiable.

### Principles I Follow

1. **Zero-knowledge** — Prove identity without revealing biometric data
2. **Post-quantum readiness** — ML-DSA-87 today, not after quantum computers arrive
3. **Defense in depth** — 10 independent security layers, no single point of failure
4. **Server-side key protection** — Private keys never leave the server (S-02 proxy)
5. **Reproducible security** — Sigstore-signed images, SBOM for every build, Trivy scans in CI
6. **Adversarial testing** — Multiple penetration test rounds, beast-level strict audits
